# LocalText2Voice 2.3.0

## Expressive speech and safer projects

- **Chatterbox Turbo:** the Emotion menu now has a Chatterbox submenu for English
  emotion/style tags and nine vocal events. Use `{{emotion happy}}` before a passage
  or `{{vocal chuckle}}` inside it. Turbo does not support emotion intensity or
  Custom descriptions; those remain IndexTTS controls. Selecting a submenu does
  not change the active engine.
- **Qwen Base voice library:** compatible reference recordings with transcripts
  can be used for cloning and selected through markup. CustomVoice preset speakers
  stay separate from Base reference voices.
- **Rename the whole project:** editing a saved project's title also updates its
  folder and internal references. Duplicate names get a suffix. Press Enter on an
  unchanged title to synchronize an older folder. Active project tasks must finish
  first; recovery protects an interrupted move.
- **Choose where exports go:** use a folder relative to the project (default:
  `exports`) or a fixed absolute folder. Existing external output locations are
  retained. The separate option to save narration next to its source still takes
  precedence when enabled.

## Reliability and responsiveness

- Safer WAV publication keeps the previous usable audio if synthesis fails and
  retries transient Windows file locks without rerunning synthesis.
- Review, Audio Mix and generation release playback handles before conflicting
  writes. Valid replacement candidates are retained if publication is blocked.
- Settings calculates WAV cache usage in the background. Opening a large project
  batches editor restoration and highlighting instead of repeating that work.
- Chatterbox consistently uses its managed Hugging Face model cache.
- Local API/MCP settings responses redact nested credentials and storage secrets.
- New project/output controls are translated into all 11 interface languages.

## Windows signing status

The project has been accepted into the SignPath Foundation program. Test signing
of the application EXEs and installer, Windows signature verification and silent
installation have passed on GitHub Actions. The production certificate is still
pending: this local 2.3.0 preparation is **unsigned**, not signed with the test
certificate. Public distribution must not ask users to trust the test certificate.

The private H3 workflow remains in development, not a finished public integration.
Optional engine/model licenses and hardware requirements continue to apply.

[the signing policy](../../CODE_SIGNING.md) for the current signing scope.
